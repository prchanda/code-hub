Question: https://leetcode.com/problems/binary-search-tree-iterator/description/

Explanation : https://www.youtube.com/watch?v=RXy5RzGF5wo

```cs
public class BSTIterator {
    private Stack<TreeNode> stack;

    public BSTIterator(TreeNode root) {
        stack = new Stack<TreeNode>();
        while (root != null)
        {
            stack.Push(root);
            root = root.left;
        }
    }
    
    public int Next() {
        var treeNode = stack.Pop();
        if (treeNode.right != null)
        {   
            var current = treeNode.right;
            while (current != null)
            {
                stack.Push(current);
                current = current.left;
            }
        }
        return treeNode.val;
    }
    
    public bool HasNext() {
        return stack.Count > 0;
    }
}
```

### Complexity Analysis

- **Time Complexity:**
    
    - **Constructor (`BSTIterator`):** $O(H)$, where $H$ is the height of the tree, because it pushes all left nodes of the root path onto the stack.
        
    - **`Next()`:** $O(1)$ amortized time. Even though a call might occasionally trigger a traversal down a right subtree and push multiple nodes, every node is pushed and popped from the stack at most once across the entire traversal of $N$ nodes.
        
    - **`HasNext()`:** $O(1)$ time, as it simply checks if the stack is non-empty.
        
- **Space Complexity:** $O(H)$, where $H$ is the height of the tree, required to store nodes along the current left branch in the explicit stack (up to $O(N)$ in the worst-case for a skewed tree and $O(\log N)$ for a balanced tree).
