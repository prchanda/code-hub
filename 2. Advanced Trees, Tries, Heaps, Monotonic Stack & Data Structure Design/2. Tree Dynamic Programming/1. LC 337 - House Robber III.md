Explanation : https://www.youtube.com/watch?v=nHR8ytpzz7c

```cs
public class Solution 
{
    public int Rob(TreeNode root) 
    {
        var result = DFS(root);
        return Math.Max(result.withRoot, result.withoutRoot);
    }

    private (int withRoot, int withoutRoot) DFS(TreeNode node)
    {
        if (node == null)
            return (0, 0);

        var left = DFS(node.left);
        var right = DFS(node.right);

        // If we rob this node, we CANNOT rob its immediate children
        int withRoot = node.val + left.withoutRoot + right.withoutRoot;

        // If we DON'T rob this node, we take the max possible from each subtree
        int withoutRoot = Math.Max(left.withRoot, left.withoutRoot) + 
                          Math.Max(right.withRoot, right.withoutRoot);

        return (withRoot, withoutRoot);
    }
}
```

### Complexity Analysis

Let $N$ be the total number of nodes in the binary tree and $H$ be the height of the tree.

- **Time Complexity:** $\mathcal{O}(N)$
    
    - The algorithm performs a post-order depth-first search (DFS) traversal, visiting every node in the binary tree exactly once.
        
    - At each node, it performs a constant number of basic arithmetic and comparison operations ($\mathcal{O}(1)$ time).
        
    - Hence, total time is linear with respect to the number of nodes: $\mathcal{O}(N)$.
        
- **Space Complexity:** $\mathcal{O}(H)$
    
    - **Call Stack Space:** The auxiliary memory is determined by the maximum recursion depth of the call stack, which equals the tree height $H$.
        
        - **Average / Balanced Tree Case:** $\mathcal{O}(\log N)$ recursion depth.
            
        - **Worst / Skewed Tree Case:** $\mathcal{O}(N)$ recursion depth if the tree degenerates into a single linked list.
            
    - **Heap / State Space:** $\mathcal{O}(1)$ additional memory beyond the call stack since tuple pairs are allocated on the stack.
