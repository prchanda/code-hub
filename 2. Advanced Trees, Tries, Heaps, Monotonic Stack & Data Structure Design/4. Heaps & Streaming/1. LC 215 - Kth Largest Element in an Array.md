### Quickselect

```cs
public class Solution 
{
    public int FindKthLargest(int[] nums, int k) 
    {
        int targetIndex = nums.Length - k;
        int left = 0, right = nums.Length - 1;

        while (left < right)
        {
            int pivot = nums[right];
            int partitionIndex = GetPartionIndex(nums, left, right, pivot);

            (nums[partitionIndex], nums[right]) = (nums[right], nums[partitionIndex]);

            if (partitionIndex == targetIndex)
            {
                return nums[partitionIndex];
            }

            if (partitionIndex < targetIndex)
            {
                left = partitionIndex + 1;
            }
            else
            {
                right = partitionIndex - 1;
            }
        }

        return nums[targetIndex];
    }

    private int GetPartionIndex(int[] nums, int left, int right, int pivot)
    {
        int i = left, j = i;

        while (j < right)
        {
            if (nums[j] < pivot)
            {
                (nums[i], nums[j]) = (nums[j], nums[i]);
                i++;
            }

            j++;
        }

        return i;
    }
}
```

For your **Quickselect LC 215** implementation:

|**Metric**|**Complexity**|**Details**|
|---|---|---|
|**Time Complexity**|**Average: `O(N)`**|Each partition scans the current portion of the array, and Quickselect only continues into the side containing the target index.|
|**Time Complexity**|**Worst: `O(N²)`**|If the pivot repeatedly ends up at one extreme, we scan almost the entire remaining array on every iteration.|
|**Space Complexity**|**`O(1)`**|Partitioning is done **in-place** using only a few variables; no additional array or recursion is used.|

**Problem:** Picking `nums[right]` as a fixed pivot causes $O(N^2)$ performance on sorted or reverse-sorted inputs. Introduce a **random pivot** or swap a random element with `nums[right]` before partitioning.

### Optimized Quickselect with Randomization

```cs
public class Solution
{
    private Random _random = new Random();

    public int FindKthLargest(int[] nums, int k)
    {
        int targetIndex = nums.Length - k;
        int left = 0;
        int right = nums.Length - 1;

        while (left <= right)
        {
            // Pick a random pivot to avoid O(N^2) worst-case
            int pivotIndex = _random.Next(left, right + 1);
            (nums[pivotIndex], nums[right]) = (nums[right], nums[pivotIndex]);

            int partitionIndex = GetPartitionIndex(nums, left, right, nums[right]);

            if (partitionIndex == targetIndex)
                return nums[partitionIndex];

            if (partitionIndex < targetIndex)
                left = partitionIndex + 1;
            else
                right = partitionIndex - 1;
        }

        return nums[targetIndex];
    }

    private int GetPartitionIndex(int[] nums, int left, int right, int pivot)
    {
        int i = left;

        for (int j = left; j < right; j++)
        {
            if (nums[j] <= pivot) // <= helps handle duplicates better
            {
                (nums[i], nums[j]) = (nums[j], nums[i]);
                i++;
            }
        }

        (nums[i], nums[right]) = (nums[right], nums[i]);
        return i;
    }
}
```

### Practical Alternative: Min-Heap / PriorityQueue ($O(N \log K)$)

```cs
public class Solution
{
    public int FindKthLargest(int[] nums, int k)
    {
        var minHeap = new PriorityQueue<int, int>();

        foreach (int num in nums)
        {
            minHeap.Enqueue(num, num);
            if (minHeap.Count > k)
            {
                minHeap.Dequeue();
            }
        }

        return minHeap.Peek();
    }
}
```


Instead of pushing all elements into a heap of size $N$ (which takes $O(N \log N)$), you keep the heap bounded to size $K$:

1. Iterate through all $N$ numbers.
    
2. For each number, call `Enqueue()` and conditionally `Dequeue()`, keeping the heap size at $\le K$.
    
3. Each operation takes $O(\log K)$ time.
    

- **Time Complexity:** $O(N \log K)$
    
- **Worst-case Time:** $O(N \log K)$ — guaranteed, with **no risk** of falling into an $O(N^2)$ trap.
    
- **Space Complexity:** $O(K)$ auxiliary space to store the heap elements.
