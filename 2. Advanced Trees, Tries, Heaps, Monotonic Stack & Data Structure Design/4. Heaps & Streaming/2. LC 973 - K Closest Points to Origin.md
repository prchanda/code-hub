Question: https://leetcode.com/problems/k-closest-points-to-origin/description/

Explanation: Use MaxHeap through PriorityQueue or use Quick Select (Refer LC 215)

### Using MaxHeap

```cs
public class Solution 
{
    public int[][] KClosest(int[][] points, int k) 
    {
        PriorityQueue<(int, int), long> queue = new PriorityQueue<(int, int), long>(
            Comparer<long>.Create((a, b) => b.CompareTo(a))
        );        

        foreach (int[] point in points)
        {
            var distance = (long)point[0] * point[0] + (long)point[1] * point[1];
            queue.Enqueue((point[0], point[1]), distance);

            if (queue.Count > k)
            {
                queue.Dequeue();            
            }
        }

        int[][] result = new int[queue.Count][];

        for (int index = 0; index < queue.Count; index++)
        {
            result[index] = new int[2];
        }

        int counter = 0;

        while (queue.TryDequeue(out (int x, int y) point, out long distance))
        {
            result[counter][0] = point.x;
            result[counter][1] = point.y;
            counter++;
        }

        return result;
    }
}
```

### Complexity Analysis

Let $N$ be the total number of points in `points` and $K$ be the number of closest points to return.

|**Metric**|**Complexity**|**Explanation**|
|---|---|---|
|**Time Complexity**|$O(N \log K)$|Iterating through all $N$ points takes $O(N)$ time. For each point, pushing to and potentially popping from a max-heap of maximum size $K+1$ takes $O(\log K)$ time. Extracting the final $K$ elements takes $O(K \log K)$ time.|
|**Space Complexity**|$O(K)$|The heap stores at most $K+1$ points at any given time during processing.|


### Using Quick Select

```cs
public class Solution
{
    public int[][] KClosest(int[][] points, int k)
    {
        int left = 0;
        int right = points.Length - 1;

        // We want the first k points to be the k closest.
        int targetIndex = k - 1;

        while (left <= right)
        {
            int pivotDistance = Distance(points[right]);

            int partitionIndex = Partition(points, left, right, pivotDistance);

            // Put pivot into its final position.
            (points[partitionIndex], points[right]) = (points[right], points[partitionIndex]);

            if (partitionIndex == targetIndex)
            {
                break;
            }

            if (partitionIndex < targetIndex)
            {
                left = partitionIndex + 1;
            }
            else
            {
                right = partitionIndex - 1;
            }
        }

        // First k points are the k closest.
        int[][] result = new int[k][];

        for (int i = 0; i < k; i++)
        {
            result[i] = points[i];
        }

        return result;
    }

    private int Partition(int[][] points, int left, int right, int pivotDistance)
    {
        int i = left;

        for (int j = left; j < right; j++)
        {
            if (Distance(points[j]) < pivotDistance)
            {
                (points[i], points[j]) = (points[j], points[i]);
                i++;
            }
        }

        return i;
    }

    private int Distance(int[] point)
    {
        return point[0] * point[0] + point[1] * point[1];
    }
}
```

### Complexity Analysis

Let $N$ be the total number of points in `points` and $K$ be the specified number of closest points.

| **Metric**                       | **Complexity** | **Explanation**                                                                                                                                  |
| -------------------------------- | -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Time Complexity (Average)**    | $O(N)$         | Quickselect eliminates half of the search space on each iteration on average ($N + N/2 + N/4 + \dots = 2N$).                                     |
| **Time Complexity (Worst Case)** | $O(N^2)$       | Occurs when chosen pivots are consistently extreme values (e.g., points sorted by distance with the furthest point selected as pivot each turn). |
| **Space Complexity**             | $O(K)$         | Reallocating the output slice takes $O(K)$ space. Partitioning runs in-place on the `points` array using $O(1)$ additional space.                |
