**LC 253 - Meeting Rooms II

Given an array of meeting time intervals consisting of start and end times `[[s1,e1],[s2,e2],...]` ($s_i < e_i$), find the minimum number of conference rooms required.

### Example 1

**Input:**

Plaintext

```
[[0, 30], [5, 10], [15, 20]]
```

**Output:**

Plaintext

```
2
```

**Explanation:**

- Meeting 1 runs from time 0 to 30.
    
- Meeting 2 runs from time 5 to 10. (Can use room 2)
    
- Meeting 3 runs from time 15 to 20. (Can share room 2 with Meeting 2, since Meeting 2 ends at 10)
    
- Total rooms needed: 2.
    

### Example 2

**Input:**

Plaintext

```
[[7, 10], [2, 4]]
```

**Output:**

Plaintext

```
1
```

**Explanation:**

- Meeting 1 runs from time 2 to 4.
    
- Meeting 2 runs from time 7 to 10.
    
- Since they do not overlap, they can use the exact same room.
    
- Total rooms needed: 1.
    

### Constraints

- $1 \le \text{intervals.length} \le 10^4$
    
- $0 \le s_i < e_i \le 10^6$



```cs
public class Solution
{
    public int MinMeetingRooms(int[][] intervals)
    {
        if (intervals.Length == 0)
            return 0;

        Array.Sort(intervals, (a, b) => a[0].CompareTo(b[0]));
        PriorityQueue<int, int> minHeap = new PriorityQueue<int, int>();

        foreach (int[] interval in intervals)
        {
            int start = interval[0];
            int end = interval[1];
            /*
	            Reuse the room whose meeting ends earliest
	            [0,30], [5,10], [15,20]
	            
	            2nd meeting ends earlier at T = 10, hence can be re-used by the 3rd meeting                       
            */
            if (minHeap.Count > 0 && minHeap.Peek() <= start)
            {
                minHeap.Dequeue();
            }

            // Occupy a room until 'end'
            minHeap.Enqueue(end, end);
        }

        return minHeap.Count;
    }
}
```


Think:

> **For every meeting, when does the earliest currently-used room become available?**

This immediately suggests a **Min-Heap**.

We sort meetings by start time:

```
[0,30]
[5,10]
[15,20]
```

Then maintain a min-heap containing **end times of meetings currently occupying rooms**.


If it asks:

> **"Minimum number of rooms/resources required so that overlapping activities can happen simultaneously"**

→ **Sorting + Min-Heap**

The phrase **"minimum number of resources required"** should immediately make you think **min-heap of end times**.

### Complexity Analysis

- **Time Complexity:** $\mathcal{O}(N \log N)$, where $N$ is the number of intervals. Sorting the intervals by their start times takes $\mathcal{O}(N \log N)$ time, and each interval is inserted into and removed from the min-heap at most once, which takes $\mathcal{O}(\log N)$ per operation.
    
- **Space Complexity:** $\mathcal{O}(N)$ auxiliary space, as the priority queue can store up to $N$ end times in the worst-case scenario where no meetings overlap and all rooms must be held simultaneously.
