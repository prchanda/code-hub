Question: https://leetcode.com/problems/merge-intervals/

```cs
public class Solution {
    public int[][] Merge(int[][] intervals) {
        Array.Sort(intervals, (a, b) => a[0].CompareTo(b[0]));
        List<int[]> output = new List<int[]>();
        int[] currentInterval = intervals[0];
        output.Add(currentInterval);
        
        for(int index = 1; index < intervals.Length; index++)
        {
            int currentIntervalEnd = currentInterval[1];
            int nextIntervalStart = intervals[index][0];
            int nextIntervalEnd = intervals[index][1];

            if(currentIntervalEnd >= nextIntervalStart)
            {
                currentIntervalEnd = Math.Max(currentIntervalEnd, nextIntervalEnd);
                currentInterval[1] = currentIntervalEnd;
            }
            else
            {
                int[] newInterval = new int[2]{nextIntervalStart, nextIntervalEnd};
                output.Add(newInterval);
                currentInterval = newInterval;
            }                    
        }

        return output.ToArray();
    }
}
```

### Complexity Analysis

- **Time Complexity:** $\mathcal{O}(N \log N)$, where $N$ is the number of intervals. The performance is dominated by sorting the array of intervals by their starting values. The subsequent linear pass through the sorted array takes $\mathcal{O}(N)$ time.
    
- **Space Complexity:** $\mathcal{O}(N)$ auxiliary space (or $\mathcal{O}(\log N)$ depending on the sorting implementation's stack space) to store the output list and maintain the merged intervals, excluding the memory used by the final returned array.
