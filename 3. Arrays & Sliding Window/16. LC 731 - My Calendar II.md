Question: https://leetcode.com/problems/my-calendar-ii/description/

```cs
public class MyCalendarTwo
{
    private List<int[]> nonOverlapping;
    private List<int[]> overlapping;

    public MyCalendarTwo()
    {
        nonOverlapping = new List<int[]>();
        overlapping = new List<int[]>();
    }

    public bool Book(int start, int end)
    {
        foreach (var interval in overlapping)
        {
            int s = interval[0];
            int e = interval[1];
            if (!(s >= end || start >= e))
            {
                return false;
            }
        }

        foreach (var interval in nonOverlapping)
        {
            int s = interval[0];
            int e = interval[1];
            if (!(s >= end || start >= e))
            {
                overlapping.Add(new int[] { Math.Max(s, start), Math.Min(e, end) });
            }
        }

        nonOverlapping.Add(new int[] { start, end });
        return true;
    }
}
```

nonOverlapping
    ↓
Intervals that have been booked, without necessarily tracking their double-booked portions

overlapping
    ↓
Time ranges that are already double-booked

Maintain all accepted bookings and a second list containing the regions that are already double-booked. Before accepting a new booking, Check whether it overlaps any double-booked region; if so, it would create a triple booking, so reject it. Otherwise, add every intersection with an existing booking to the double-booked list and accept the new booking.

- **Time Complexity:** $O(N)$ per `Book` call, where $N$ is the number of existing bookings. In the worst case, it iterates through both the `overlapping` and `nonOverlapping` lists linearly. For $N$ total calls, the cumulative worst-case time complexity is $O(N^2)$.
    
- **Space Complexity:** $O(N)$ in typical scenarios to store the bookings, though the `overlapping` list can grow up to $O(N^2)$ in the absolute worst-case scenario where every new booking overlaps with every prior booking.
