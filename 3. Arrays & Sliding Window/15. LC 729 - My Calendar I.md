```cs
public class MyCalendar
{
    private List<int[]> bookings;

    public MyCalendar()
    {
        bookings = new List<int[]>();
    }

    public bool Book(int startTime, int endTime)
    {
        foreach (int[] booking in bookings)
        {
            int start = booking[0];
            int end = booking[1];

            // Overlap exists if:
            // startTime < end && start < endTime
            if (!(startTime >= end || start >= endTime))
            {
                return false;
            }
        }

        bookings.Add(new int[] { startTime, endTime });
        return true;
    }
}
```

- **Time Complexity:** $O(N)$ per `Book` call, where $N$ is the number of existing bookings, because it linearly checks against every prior booking. For $N$ total calls, the worst-case time complexity is $O(N^2)$.
    
- **Space Complexity:** $O(N)$ to store the bookings in the list.



```cs
private class Node
{
	public int Start;
	public int End;
	public Node Left;
	public Node Right;

	public Node(int start, int end)
	{
		Start = start;
		End = end;
	}
}

public class MyCalendar
{   
    private Node root;

	public bool Book(int start, int end)
    {
        if (root == null)
        {
            root = new Node(start, end);
            return true;
        }

        return Insert(root, start, end);
    }

    private bool Insert(Node rootNode, int start, int end)
    {
        Node curr = rootNode;
        while (true)
        {
            if (start >= curr.End)
            {
                if (curr.Right == null)
                {
                    curr.Right = new Node(start, end);
                    return true;
                }
                curr = curr.Right;
            }
            else if (end <= curr.Start)
            {
                if (curr.Left == null)
                {
                    curr.Left = new Node(start, end);
                    return true;
                }
                curr = curr.Left;
            }
            else
            {
                return false;
            }
        }
    }
}
```

- **Time Complexity:** $O(N)$ on average or $O(N^2)$ in the worst case per `Book` call, where $N$ is the number of bookings. Because this is a standard binary search tree rather than a self-balancing tree (like an AVL or Red-Black tree), it can degrade to a linear structure if bookings are made in sequential sorted order.
    
- **Space Complexity:** $O(N)$ to store the nodes in the binary search tree.


While it avoids scanning every element linearly like a simple list, it uses a **standard, unbalanced Binary Search Tree**.

- **The Flaw:** If bookings arrive in sequential, sorted order (e.g., `[1, 2]`, then `[2, 3]`, then `[3, 4]`), the tree degenerates into a linked list.
    
- **Worst-Case Performance:** The height of the tree becomes $O(N)$, making the time complexity for a single `Book` call $O(N)$ and the overall time complexity for $N$ calls $O(N^2)$—the exact same worst-case performance as a simple `List<int[]>`.
    

To make it truly optimized, it needs to be a **self-balancing BST** (such as an AVL Tree or Red-Black Tree) which guarantees a height of $O(\log N)$ and an overall time complexity of $O(N \log N)$. In C#, using `SortedDictionary<int, int>` handles this balancing automatically under the hood.
