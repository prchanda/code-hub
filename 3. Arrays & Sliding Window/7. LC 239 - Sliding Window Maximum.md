Question: https://leetcode.com/problems/sliding-window-maximum/

Explanation: https://leetcode.com/problems/sliding-window-maximum/description/


```cs
public class Solution
{
    public int[] MaxSlidingWindow(int[] nums, int k)
    {
        int n = nums.Length;

        // Stores indices.
        // Values are maintained in decreasing order.
        LinkedList<int> deque = new LinkedList<int>();

        List<int> result = new List<int>();

        for (int index = 0; index < n; index++)
        {
            // 1. Remove indices that are outside the current window.
            while (deque.Count > 0 &&
                   deque.First.Value <= index - k)
            {
                deque.RemoveFirst();
            }

            // 2. Remove elements smaller than or equal to nums[index].
            //    They can never become the maximum while nums[index]
            //    is inside the window.
            while (deque.Count > 0 &&
                   nums[deque.Last.Value] <= nums[index])
            {
                deque.RemoveLast();
            }

            // 3. Add current index.
            deque.AddLast(index);

            // 4. Once we have a complete window,
            //    the front contains the maximum.
            if (index >= k - 1)
            {
                result.Add(nums[deque.First.Value]);
            }
        }

        return result.ToArray();
    }
}
```

### Complexity Analysis

- **Time Complexity:** $\mathcal{O}(N)$, where $N$ is the number of elements in the `nums` array. Each index is added to and removed from the deque at most once, making the amortized time complexity per element constant.
    
- **Space Complexity:** $\mathcal{O}(K)$ auxiliary space, as the deque stores at most $K$ indices at any given time within the sliding window, excluding the space for the output array.
