
Question: https://leetcode.com/problems/target-sum/

```cs
public class Solution
{
    public int FindTargetSumWays(int[] nums, int target)
    {
        int total = 0;

        foreach (int num in nums)
        {
            total += num;
        }

        // Impossible if target sum parity is invalid or target is out of achievable bounds [-total, total]
        /*
	        Let's divide the numbers into two groups:
			
			- `P` = numbers given `+`
			- `N` = numbers given `-`
        
	        P - N = target
		    P + N = sum
		    
		    2P = sum + target
		    P = (sum + target) / 2
		    
		    `P` must be an **integer** because we're adding whole integers.
        
        */
        if ((total + target) % 2 != 0 || Math.Abs(target) > total)
        {
            return 0;
        }

        // Reduces problem to 0/1 Knapsack: find count of subsets that sum to subsetTarget
        int subsetTarget = (total + target) / 2;

        // dp[sum] stores the number of ways to achieve a subset sum equal to 'sum'
        int[] dp = new int[subsetTarget + 1];

        // Base case: 1 way to form sum 0 (by selecting an empty subset)
        dp[0] = 1;

        // Dynamic programming traversal
        foreach (int num in nums)
        {
            // Traverse backward to ensure each number is used at most once per subset
            for (int sum = subsetTarget; sum >= num; sum--)
            {
                dp[sum] += dp[sum - num];
            }
        }

        return dp[subsetTarget];
    }
}
```

## Complexity Analysis

Let $n$ be the number of elements in `nums` (`nums.Length`), and $P = \frac{\text{total} + \text{target}}{2}$ be the target sum for the positive subset (`subsetTarget`).

### Time Complexity: $\mathcal{O}(n \times P)$

- **Total Sum Computation:** The initial `foreach` loop sums elements in $\mathcal{O}(n)$ time.
    
- **DP Execution:** The outer loop processes each of the $n$ numbers. The inner loop executes up to $P + 1$ times for each number.
    
- **Total Time:** $\mathcal{O}(n) + \mathcal{O}(n \times P) = \mathcal{O}(n \times P)$ pseudo-polynomial time.
    

### Space Complexity: $\mathcal{O}(P)$

- **DP Array:** A 1D dynamic programming array `dp` of size $P + 1$ is allocated.
    
- **Auxiliary Space:** Uses $\mathcal{O}(1)$ additional memory for scalar primitive variables.
    
- **Total Space:** $\mathcal{O}(P)$ auxiliary space.

# Let's use a correct example

Let's use the standard:

nums = [1, 1, 1, 1, 1]

target = 3

We need to find assignments that produce `3`.

One valid assignment is:

+1 +1 +1 +1 -1

Now divide them into two groups.

### Positive numbers

P = 1 + 1 + 1 + 1

  = 4

### Negative numbers

N = 1

Therefore:

P - N

= 4 - 1

= 3

Perfect.

---

# 3. Why do we write `P - N = target`?

Because that's literally what the `+` and `-` operations mean.

Every number is put into one of two groups:

              numbers

                 │

          ┌──────┴──────┐

          ↓             ↓

       Positive       Negative

          P              N

The final expression is:

+ positive numbers

- negative numbers

So:

result = P - N

And the problem says:

> Make the result equal to `target`.

Therefore:

P - N = target

If target happens to be negative, that's perfectly fine.

For example:

P = 2

N = 5

  

P - N = -3

So:

target = -3

Nothing wrong with that.

---

# 4. Why do we also say `P + N = total`?

Because **every number must go somewhere**.

It either gets a:

+

or:

-

So all numbers are accounted for between `P` and `N`.

Therefore:

P + N = total

For:

[1,1,1,1,1]

we have:

P + N = 5

---

# 5. Now we have TWO equations

This is the key transformation:

P - N = target

P + N = total

Let's use:

target = 3

total = 5

Therefore:

P - N = 3

P + N = 5

Add them:

(P - N) + (P + N) = 3 + 5

`-N` and `+N` cancel:

2P = 8

Therefore:

P = 4

---

# 6. So what does that mean?

Instead of asking:

> "Where should I put `+` and `-`?"

we can ask:

> **"Which numbers should belong to the positive group, whose sum must be 4?"**

For:

[1,1,1,1,1]

we need to choose numbers adding to:

4

For example:

1 + 1 + 1 + 1 = 4

The remaining `1` goes into the negative group:

P = 4

N = 1

and:

4 - 1 = 3

Exactly what we wanted.

---

# 7. And this is why LC 494 is called State Transformation

We're taking:

+ / - assignment problem

and transforming it into:

subset-sum problem

The transformation is:

P - N = target

P + N = total

  

        ↓

  

2P = target + total

  

        ↓

  

P = (target + total) / 2

Then:

> **How many subsets can produce `P`?**

---

## One important edge case

Because:

P = (target + total) / 2

`target + total` must be **even**.

If it's odd, there is no integer `P`.

For example:

total = 5

target = 2

  

target + total = 7

You can't have:

P = 7 / 2 = 3.5

A subset sum can't be `3.5` when all our numbers are integers.

So the answer is immediately:

false / 0 ways
