Question: https://leetcode.com/problems/profitable-schemes/description/

```cs
public class Solution
{
    public int ProfitableSchemes(int n, int minProfit, int[] group, int[] profit)
    {
        const int MOD = 1_000_000_007;

        // dp[people, currentProfit] stores the number of schemes using 'people' generating 'currentProfit'
        int[,] dp = new int[n + 1, minProfit + 1];

        // Base case: 1 way to use 0 people and make 0 profit (by choosing nothing)
        dp[0, 0] = 1;

        // Iterative 0/1 Knapsack optimization
        for (int job = 0; job < group.Length; job++)
        {
            int peopleNeeded = group[job];
            int profitGenerated = profit[job];

            // Traverse backward for people to ensure each job is used at most once
            for (int people = n - peopleNeeded; people >= 0; people--)
            {
                for (int currentProfit = 0; currentProfit <= minProfit; currentProfit++)
                {
                    if (dp[people, currentProfit] == 0)
                    {
                        continue;
                    }

                    int newPeople = people + peopleNeeded;
                    int newProfit = Math.Min(minProfit, currentProfit + profitGenerated);

                    dp[newPeople, newProfit] = (dp[newPeople, newProfit] + dp[people, currentProfit]) % MOD;
                }
            }
        }

        // Sum all schemes that use at most 'n' people and yield at least 'minProfit'
        int answer = 0;
        for (int people = 0; people <= n; people++)
        {
            answer = (answer + dp[people, minProfit]) % MOD;
        }

        return answer;
    }
}

```

## Complexity Analysis

Let $K$ be the total number of jobs (`group.Length`), $n$ be the maximum available group members (`n`), and $P$ be the minimum profit required (`minProfit`).

### Time Complexity: $\mathcal{O}(K \times n \times P)$

- **Triple Nested Loop:**
    
    - The outer loop runs $K$ times (processing each job).
        
    - The middle loop runs at most $n + 1$ times for `people`.
        
    - The inner loop runs $P + 1$ times for `currentProfit`.
        
- **Final Aggregation Loop:** Runs $n + 1$ times in $\mathcal{O}(n)$ time.
    
- **Total Time:** $\mathcal{O}(K \times n \times P)$ pseudo-polynomial time.
    

### Space Complexity: $\mathcal{O}(n \times P)$

- **Optimized DP Array:** By iterating `people` backward, space is optimized from 3D $\mathcal{O}(K \times n \times P)$ down to a 2D array of size $(n + 1) \times (P + 1)$.
    
- **Auxiliary Space:** Primitive loop variables consume $\mathcal{O}(1)$ space.
    
- **Total Space:** $\mathcal{O}(n \times P)$ auxiliary space.
