```cs
// Recursive Solution

public int LengthOfLIS(int[] nums)
{
    return LIS(nums, 0, -1);
}

private int LIS(int[] nums, int i, int prev)
{
    // No elements left
    if (i == nums.Length)
        return 0;

    // Option 1: skip nums[i]
    

    // Option 2: take nums[i]
    int take = 0;

    if (prev == -1 || nums[i] > nums[prev])
    {
        take = 1 + LIS(nums, i + 1, i);
    }
    
    int skip = LIS(nums, i + 1, prev);

    return Math.Max(take, skip);
}
```


# Top-Down approach

```cs

// Top-Down approach, since there are 2 variables, so its a 2D DP

public int LengthOfLIS(int[] nums)
{
    int n = nums.Length;

    int[,] dp = new int[n, n + 1];

    for (int i = 0; i < n; i++)
        for (int j = 0; j < n + 1; j++)
            dp[i, j] = -1;

    return LIS(nums, 0, -1, dp);
}

private int LIS(int[] nums, int i, int prev, int[,] dp)
{
    if (i == nums.Length)
        return 0;

    if (dp[i, prev + 1] != -1)
        return dp[i, prev + 1];

    // Skip
    int skip = LIS(nums, i + 1, prev, dp);

    // Take
    int take = 0;

    if (prev == -1 || nums[i] > nums[prev])
    {
        take = 1 + LIS(nums, i + 1, i, dp);
    }

    dp[i, prev + 1] = Math.Max(take, skip);

    return dp[i, prev + 1];
}

```

# Bottom-up approach

```cs
using System;
using System.Linq;

public class Solution 
{
    public int LengthOfLIS(int[] nums) 
    {
        if (nums == null || nums.Length == 0) return 0;

        int size = nums.Length;
        int[] dp = new int[size];

        // Initialize every element's minimum LIS length to 1
        for (int i = 0; i < size; i++)
        {
            dp[i] = 1;
        }

        // Bottom-up Dynamic Programming
        for (int i = 0; i < size; i++)
        {
            for (int j = 0; j < i; j++)
            {
                if (nums[j] < nums[i])
                {
                    // dp[i] will be atleast 1 greater in length than dp[j], hence we are checking
                    // whether we have already have max LIS at i or not. If we already have ignore it
                    // else add 1 to it, hence the below line
                    dp[i] = Math.Max(dp[i], dp[j] + 1);
                }
            }
        }

        return dp.Max();
    }
}
```

### Complexity Analysis

Let $n$ be the length of the input array `nums`.

- **Time Complexity:** $\mathcal{O}(n^2)$
    
    - The outer loop runs $n$ times.
        
    - For each index $i$, the inner loop runs $i$ times ($0 + 1 + 2 + \dots + (n-1) = \frac{n(n-1)}{2}$ iterations total).
        
    - Inside the loops, comparison and assignment take $\mathcal{O}(1)$ time. Finding the max at the end takes $\mathcal{O}(n)$ time.
        
- **Space Complexity:** $\mathcal{O}(n)$
    
    - The `dp` array requires $\mathcal{O}(n)$ auxiliary memory to store the LIS value for each index.
        

> **Tip:** This dynamic programming approach runs in $\mathcal{O}(n^2)$ time. You can optimize this problem to **$\mathcal{O}(n \log n)$ time** using a greedy approach paired with **Binary Search** (Patience Sorting) by maintaining an array of the smallest tail elements.


The key idea is to maintain an array called `tails`. What does `tails` mean? We're maintaining the **best possible tail** for each length, because having a smaller ending value gives us more opportunity to extend later. A smaller tail preserves the same subsequence length while giving us more possibilities to extend it in the future. And the algorithm's guarantee comes from maintaining the **best tail for every possible length**, not from predicting which elements will eventually form the LIS.

`tails[k]` = **the smallest possible ending value of an increasing subsequence of length `k + 1` found so far.**

```cs
public class Solution 
{
    public int LengthOfLIS(int[] nums) 
    {
        if (nums == null || nums.Length == 0) 
	        return 0;

        List<int> tail = new List<int>();

        foreach (int num in nums) 
        {
            int left = 0;
            int right = tail.Count;

            // Binary search to find the smallest element in 'tail' >= 'num'
            while (left < right) 
            {
                int mid = left + (right - left) / 2;

                if (num > tail[mid]) 
                {
                    left = mid + 1;
                } 
                else 
                {
                    right = mid;
                }
            }

            // If num is larger than all elements in tail, extend the LIS
            if (left == tail.Count) 
            {
                tail.Add(num);
            } 
            else 
            {
                // Otherwise, replace the element to keep tail values as small as possible
                tail[left] = num;
            }
        }

        return tail.Count;
    }
}
```

### Complexity Analysis

Let $n$ be the length of the input array `nums`.

- **Time Complexity:** $\mathcal{O}(n \log n)$
    
    - The outer loop iterates through all $n$ elements in `nums`.
        
    - For each element, a binary search is performed on the `tail` list. Since the size of `tail` is at most $n$, the binary search takes $\mathcal{O}(\log n)$ time.
        
    - Adding to or updating the `tail` list takes $\mathcal{O}(1)$ amortized time.
        
    - Overall time is $n \times \mathcal{O}(\log n) = \mathcal{O}(n \log n)$.
        
- **Space Complexity:** $\mathcal{O}(n)$
    
    - In the worst-case scenario (where the array is strictly increasing), the `tail` list will grow to hold $n$ elements.
