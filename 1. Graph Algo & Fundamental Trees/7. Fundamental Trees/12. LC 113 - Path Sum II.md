Question: https://leetcode.com/problems/path-sum-ii/description/

```cs
public class Solution
{
    private IList<IList<int>> result;

    public IList<IList<int>> PathSum(TreeNode root, int targetSum)
    {
        result = new List<IList<int>>();
        List<int> path = new List<int>();

        PathSumHelper(root, targetSum, 0, path);

        return result;
    }

    private void PathSumHelper(TreeNode node, int targetSum, int currentSum, List<int> path)
    {
        if (node == null)
            return;

        currentSum += node.val;
        path.Add(node.val);

        // Must be a leaf
        if (node.left == null && node.right == null && currentSum == targetSum)
        {
            result.Add(new List<int>(path));
        }
        else
        {
            PathSumHelper(node.left, targetSum, currentSum, path);
            PathSumHelper(node.right, targetSum, currentSum, path);
        }

        // Backtrack
        path.RemoveAt(path.Count - 1);
    }
}
```

### Complexity Analysis

- **Time Complexity:** $O(N^2)$ in the worst-case (or $O(N \log N)$ for a balanced binary tree), where $N$ is the number of nodes. Every node is visited once during the depth-first search ($O(N)$ time), but for each valid root-to-leaf path found, copying the path elements to the result list takes proportional to the path's length (tree height $H$). In a skewed tree, this can result in $O(N^2)$ time.
    
- **Space Complexity:** $O(N)$ in the worst-case (or $O(H)$ where $H$ is the tree height) auxiliary space. This accounts for the recursion call stack and the temporary `path` list used for backtracking. (Note: Additional space is required to store the output results depending on the number of valid paths).
