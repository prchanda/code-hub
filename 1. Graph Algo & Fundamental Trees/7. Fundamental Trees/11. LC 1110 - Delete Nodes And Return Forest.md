Question: https://leetcode.com/problems/delete-nodes-and-return-forest/description/

```cs
public class Solution
{
    public IList<TreeNode> DelNodes(TreeNode root, int[] to_delete)
    {
        var result = new List<TreeNode>();
        var deleteSet = new HashSet<int>(to_delete);

        Dfs(root, true, deleteSet, result);

        return result;
    }

    private TreeNode Dfs(
        TreeNode node,
        bool isRoot,
        HashSet<int> deleteSet,
        List<TreeNode> result)
    {
        if (node == null)
            return null;

        bool deleted = deleteSet.Contains(node.val);

        // If this node is a root and survives, it becomes a root in our answer.
        if (isRoot && !deleted)
            result.Add(node);

        // If current node is deleted, its children may become new roots.
        node.left = Dfs(node.left, deleted, deleteSet, result);
        node.right = Dfs(node.right, deleted, deleteSet, result);

        // Tell the parent whether this node still exists.
        return deleted ? null : node;
    }
}
```

### Complexity Analysis

- **Time Complexity:** $O(N + M)$, where $N$ is the number of nodes in the binary tree and $M$ is the number of elements in the `to_delete` array. Constructing the `HashSet` takes $O(M)$ time, and the DFS traversal visits each node in the tree exactly once with $O(1)$ set lookups.
    
- **Space Complexity:** $O(N + M)$. The `deleteSet` requires $O(M)$ space, the recursion call stack takes $O(H)$ space (where $H$ is the tree height, ranging from $O(\log N)$ for a balanced tree to $O(N)$ for a skewed tree), and the `result` list can store up to $O(N)$ roots in the worst-case scenario.
