You are given a village with **`n` houses**, numbered from `1` to `n`.

You want to supply water to every house.

There are **two ways** to provide water:

1. **Build a well inside a house**
    - `wells[i - 1]` is the cost of building a well in house `i`.
2. **Connect two houses with a pipe**
    - `pipes[j] = [house1, house2, cost]`
    - This means you can connect `house1` and `house2` with a pipe costing `cost`.

Water can flow through connected pipes, so a house doesn't necessarily need its own well if it can receive water through pipes from another house that has a well.

### Goal

Return the **minimum total cost** needed to supply water to **every house**.

### Example 1

```
n = 3

wells = [1, 2, 2]

pipes = [
    [1, 2, 1],
    [2, 3, 1]
]
```

One optimal solution is:

```
Build well at house 1 → cost 1

Connect 1 ──1── 2
Connect 2 ──1── 3
```

Total:

```
1 + 1 + 1 = 3
```

So the answer is:

```
3
```

---

### Example 2

```
n = 2

wells = [1, 1]

pipes = [
    [1, 2, 1]
]
```

We could:

```
Build well at house 1 → 1
Build well at house 2 → 1

Total = 2
```

Or:

```
Build well at house 1 → 1
Connect 1 ──1── 2

Total = 2
```

Answer:

```
2
```


```cs
public int MinCostToSupplyWater(int n, int[] wells, int[][] pipes)
{
    // n well edges + all pipe edges
    int[][] edges = new int[n + pipes.Length][];

    // Virtual node 0 -> every house
    for (int i = 1; i <= n; i++)
    {
        edges[i - 1] = new int[3];

        edges[i - 1][0] = 0;
        edges[i - 1][1] = i;
        edges[i - 1][2] = wells[i - 1];
    }

    // Add pipe edges
    for (int i = 0; i < pipes.Length; i++)
    {
        edges[n + i] = new int[3];

        edges[n + i][0] = pipes[i][0];
        edges[n + i][1] = pipes[i][1];
        edges[n + i][2] = pipes[i][2];
    }

    // Kruskal
    Array.Sort(edges, (a, b) => a[2].CompareTo(b[2]));

    int[] parent = new int[n + 1];
    int[] rank = new int[n + 1];

    for (int i = 0; i <= n; i++)
    {
        parent[i] = i;
    }

    int result = 0;
    int edgesUsed = 0;

    foreach (var edge in edges)
    {
        int from = edge[0];
        int to = edge[1];
        int cost = edge[2];

        if (Union(from, to, parent, rank))
        {
            result += cost;
            edgesUsed++;

            if (edgesUsed == n)
                break;
        }
    }

    return result;
}

private bool Union(int nodeA, int nodeB, int[] parent, int[] rank)
{
    int rootA = Find(nodeA, parent);
    int rootB = Find(nodeB, parent);

    if (rootA == rootB)
        return false;

    if (rank[rootA] < rank[rootB])
    {
        parent[rootA] = rootB;
    }
    else if (rank[rootB] < rank[rootA])
    {
        parent[rootB] = rootA;
    }
    else
    {
        parent[rootB] = rootA;
        rank[rootA]++;
    }

    return true;
}

private int Find(int node, int[] parent)
{
    if (parent[node] != node)
        parent[node] = Find(parent[node], parent);

    return parent[node];
}
```


### **Complexity Analysis**

- **Time Complexity:** $O(E \log E)$ where $E$ is the total number of edges, which is equal to $n + P$ (where $n$ is the number of houses/wells and $P$ is the number of pipes).
    
    - **Edge Construction:** Building the combined edge array of size $n + P$ takes $O(n + P)$ time.
        
    - **Sorting:** Sorting the `edges` array of size $E$ based on costs takes $O(E \log E)$ time.
        
    - **Union-Find Operations:** Initializing the arrays takes $O(n)$ time. Iterating through the edges and performing `Find`/`Union` with path compression and union by rank takes $O(E \cdot \alpha(n))$ time, where $\alpha$ is the Inverse Ackermann function.
        
    - **Total Time:** Dominated by the sorting step, yielding $O((n + P) \log(n + P))$.
        
- **Space Complexity:** $O(n + P)$
    
    - The `edges` array stores $n$ well edges and $P$ pipe edges, requiring $O(n + P)$ space.
        
    - The `parent` and `rank` arrays each require $O(n)$ space.
        
    - The recursive `Find` stack uses $O(n)$ space in the worst case.
