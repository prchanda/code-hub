Question: https://leetcode.com/problems/number-of-operations-to-make-network-connected/

Using DFS, we'd have to repeatedly traverse the graph. But imagine thousands of edges. That's where **Union-Find** becomes useful.
I don't care about the actual paths between nodes. I only care which connected component each node belongs to.

```cs
public class Solution 
{
    public int MakeConnected(int n, int[][] connections) 
    {
        // To connect n computers, we need at least n - 1 cables
        if (connections.Length < n - 1) 
        {
            return -1;
        }
        
        // Lets assume each node initially represents each individual component
        // Hence number of connected component = n
        int components = n;
        int[] parents = new int[n];

        // Initialize each node as its own root
        for (int i = 0; i < n; i++) 
        {
            parents[i] = i;
        }

        // Union connected nodes
        foreach (int[] connection in connections) 
        {
            int nodeA = connection[0];
            int nodeB = connection[1];

            int rootA = Find(nodeA, parents);
            int rootB = Find(nodeB, parents);

            if (rootA != rootB) 
            {
                parents[rootB] = rootA;
                // Keep descreasing the connected component when we are using union 
                // operation to part of the same connected component
                components--;
            }
        }

        // Minimum operations needed to connect all components
        return components - 1;
    }

    private int Find(int node, int[] parents) 
    {
        if (parents[node] == node) 
        {
            return node;
        }

        // Path compression: points directly to the root node
        return parents[node] = Find(parents[node], parents);
    }
}
```

## Complexity Analysis

Let **$V = n$** be the number of computers (nodes) and **$E = \text{connections.Length}$** be the number of cables (edges).

### Time Complexity: $O(V + E \cdot \alpha(V))$

- **Initialization:** $O(V)$ to initialize the `parents` array.
    
- **Union-Find Operations:** The code processes $E$ edges. For each edge, it calls `Find` twice. Because `Find` uses **path compression**, each query runs in nearly constant amortized time, bounded by $O(\alpha(V))$, where $\alpha$ is the Inverse Ackermann function.
    
- Since $\alpha(V) \le 4$ for all realistic values of $V$, this operates in **effectively $O(V + E)$** time.
    

### Space Complexity: $O(V)$

- **Parents Array:** $O(V)$ auxiliary space to store parent pointers for $n$ nodes.
    
- **Recursion Stack:** Up to $O(V)$ call stack depth in the worst case during initial unflattened `Find` calls, which quickly flattens to $O(\log V)$ or near $O(1)$ as path compression updates parent pointers.
