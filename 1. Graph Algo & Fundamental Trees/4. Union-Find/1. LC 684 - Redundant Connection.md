
Question: https://leetcode.com/problems/redundant-connection/

Using DFS, we'd have to repeatedly traverse the graph. But imagine thousands of edges. That's where **Union-Find** becomes useful.
I don't care about the actual paths between nodes. I only care which connected component each node belongs to.

```cs
public class Solution 
{
    public int[] FindRedundantConnection(int[][] edges) 
    {
        int n = edges.Length;
        int[] parent = new int[n + 1];

        // Initialize each node as its own parent
        for (int index = 1; index <= n; index++)
        {
            parent[index] = index;
        }

        foreach (int[] edge in edges)
        {
            int nodeA = edge[0];
            int nodeB = edge[1];

            int rootA = Find(nodeA, parent);
            int rootB = Find(nodeB, parent);

            // If both nodes share the same root, adding this edge creates a cycle
            if (rootA == rootB)
            {
                return edge;
            }

            // Union operation: attach one tree to the other
            parent[rootB] = rootA;
        }

        return new int[2];
    }

    // Find operation with Path Compression
    private int Find(int node, int[] parent)
    {
        if (parent[node] == node)
        {
            return node;
        }

        // Flatten the tree during traversal
        parent[node] = Find(parent[node], parent);
        return parent[node];
    }
}
```

| **Metric**           | **Complexity**                                          |
| -------------------- | ------------------------------------------------------- |
| **Time Complexity**  | $\mathcal{O}(N \cdot \alpha(N)) \approx \mathcal{O}(N)$ |
| **Space Complexity** | $\mathcal{O}(N)$                                        |

_Note: $\alpha$ is the **Inverse Ackermann function**, which grows so slowly that $\alpha(N) < 5$ for all practical values of $N$, making it effectively constant time._

#### Time Complexity: $\mathcal{O}(N \cdot \alpha(N))$

1. **Initialization:** Setting up the `parent` array takes $\mathcal{O}(N)$ time.
    
2. **Edge Iteration:** The `foreach` loop runs $N$ times. In each iteration, `Find` is called twice.
    
3. **Find Operation:** Because you included **Path Compression** (`parent[node] = Find(...)`), the tree height collapses during lookups. Amortized across all operations, `Find` runs in nearly constant time $\mathcal{O}(\alpha(N))$.
    
4. **Total Time:** $\mathcal{O}(N) + N \times \mathcal{O}(\alpha(N)) = \mathcal{O}(N \cdot \alpha(N))$.
    

#### Space Complexity: $\mathcal{O}(N)$

1. **Parent Array:** The `parent` array stores $N + 1$ elements, taking $\mathcal{O}(N)$ auxiliary space.
    
2. **Recursion Call Stack:** In the worst-case scenario before path compression flattens the trees, the recursive `Find` function can reach a maximum depth of $N$, using $\mathcal{O}(N)$ stack memory.
    
3. **Total Space:** $\mathcal{O}(N) + \mathcal{O}(N) = \mathcal{O}(N)$.
