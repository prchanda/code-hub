### **Problem Statement**

There are $n$ cities labeled from $1$ to $n$.

You are given an integer $n$ and an array `connections` where `connections[i] = [xi, yi, costi]` indicates that the cost of connecting city `xi` and city `yi` (a bidirectional connection) is `costi`.

Return the **minimum cost** so that for every pair of cities, there exists a path of connections (possibly of length 1) that connects those two cities together. The cost is the sum of the connection costs used. If the task is impossible (i.e., not all cities can be connected), return `-1`.

### **Examples**

#### **Example 1:**

- **Input:** $n = 3$, `connections = [[1,2,5],[1,3,6],[2,3,1]]`
    
- **Output:** `6`
    
- **Explanation:** Choosing the connections between cities `1 & 2` (cost 5) and cities `2 & 3` (cost 1) gives a total cost of $5 + 1 = 6$, which connects all cities together. (Choosing any 2 edges will connect all cities, so we choose the minimum 2).
    

#### **Example 2:**

- **Input:** $n = 4$, `connections = [[1,2,3],[3,4,4]]`
    
- **Output:** `-1`
    
- **Explanation:** There is no way to connect all four cities because cities $1$ and $2$ form one isolated component, and cities $3$ and $4$ form another with no bridge between them.
    

### **Constraints:**

- $1 \le n \le 10^4$
    
- $1 \le \text{connections.length} \le 10^4$
    
- `connections[i].length == 3`
    
- $1 \le x_i, y_i \le n$
    
- $1 \le \text{cost}_i \le 10^4$
    
- $x_i \neq y_i$


```cs
public int minimumCost(int n, int[][] connections)
{
	Array.Sort(connections, (a,b) => a[2].CompareTo(b[2]));
	int[] parent = new int[n + 1];
	int[] rank = new int[n +1];
	for(int currentIndex=1; currentIndex<=n; currentIndex++)
	{
		parent[currentIndex] = currentIndex;
	}
	
	int result = 0;
	int edgesUsed = 0;
	foreach(var connection in connections)
	{
		int from = connection[0];
		int to = connection[1];
		int cost = connection[2];		
		if(Union(from, to, parent, rank))
		{
			edgesUsed++;
			result+=cost;
		}
	}	
	return edgesUsed == n-1 ? result : -1;
}


private bool Union(int nodeA, int nodeB, int[] parent, int[] rank)
{
	int rootA = Find(nodeA, parent);
	int rootB = Find(nodeB, parent);
	
	if(rootA == rootB)
		return false;
		
	if(rank[rootA]<rank[rootB])
		parent[rootA] = rootB;
	else if(rank[rootB]<rank[rootA])
		parent[rootB] = rootA; 
	else
	{
		parent[rootB] = rootA; 
		rank[rootA]++;
	}
	
	return true;
}

private int Find(int node, int[] parent)
{
	if(parent[node] != node)
		parent[node] = Find(parent[node], parent);
	return parent[node];
}
```

### **Complexity Analysis**

- **Time Complexity:** $O(E \log E)$ (or $O(E \log n)$) where $E$ is the number of connections and $n$ is the number of cities.
    
    - **Sorting:** Sorting the `connections` array based on their costs takes $O(E \log E)$ time. Since $E \le n(n-1)/2$, this can also be expressed as $O(E \log n)$.
        
    - **Union-Find Operations:** Initializing the arrays takes $O(n)$ time. Iterating through the $E$ edges and performing `Find`/`Union` with path compression and union by rank takes nearly constant time per edge, specifically $O(E \cdot \alpha(n))$ where $\alpha$ is the Inverse Ackermann function.
        
    - **Total Time:** Dominated by the sorting step, giving $O(E \log E)$.
        
- **Space Complexity:** $O(n)$
    
    - The `parent` and `rank` arrays each require $O(n)$ space.
        
    - The recursive `Find` method uses a call stack proportional to the tree height, which is bounded by $O(n)$ in the worst case (though practically flattened to near $O(1)$ due to path compression).
