A graph is **bipartite** if the nodes can be partitioned into two independent sets `A` and `B` such that **every** edge in the graph connects a node in set `A` and a node in set `B`

The key idea is:

> **Can we color every node with one of two colors such that every edge connects nodes of different colors?**

```cs

public class Solution 
{
    public bool IsBipartite(int[][] graph) 
    {
        int noOfNodes = graph.Length;
        int[] color = new int[noOfNodes];

        // Initialize all nodes as uncolored (-1)
        Array.Fill(color, -1);

        // Loop handles disconnected graph components
        for (int index = 0; index < noOfNodes; index++)
        {
            if (color[index] == -1)
            {
                color[index] = 0; // Start coloring with initial color 0
                
                if (!DFS(graph, index, color))
                {
                    return false;
                }
            }
        }

        return true;
    }

    private bool DFS(int[][] graph, int node, int[] color)
    {
        foreach (var neighbour in graph[node])
        {
            // If neighbour is uncolored, assign opposite color (1 - current) and recurse
            if (color[neighbour] == -1)
            {
                color[neighbour] = 1 - color[node];
                
                if (!DFS(graph, neighbour, color))
                {
                    return false;
                }
            }
            // If neighbour shares the same color, conflict found -> not bipartite
            else if (color[neighbour] == color[node])
            {
                return false;
            }
        }

        return true;
    }
}
```


## Complexity Breakdown

|**Metric**|**Complexity**|
|---|---|
|**Time Complexity**|$\mathcal{O}(V + E)$|
|**Space Complexity**|$\mathcal{O}(V)$|

_Where **$V$** is the number of vertices (nodes, `graph.Length`) and **$E$** is the total number of edges in the graph._

### Time Complexity: $\mathcal{O}(V + E)$

- **Vertex Operations ($\mathcal{O}(V)$):**
    - Initializing and filling the `color` array takes $\mathcal{O}(V)$ time.        
    - The outer `for` loop runs $V$ times. Each node is assigned a color ($0$ or $1$) and visited by `DFS` **at most once**, as unvisited nodes must have `color[i] == -1`.
        
- **Edge Operations ($\mathcal{O}(E)$):**
    - Inside `DFS`, the `foreach` loop iterates over `graph[index]`, which contains only the actual neighbors of that node.
    - Across all recursive DFS calls, every edge is examined exactly twice (once from each endpoint).
        
- **Total Time:** $\mathcal{O}(V) + \mathcal{O}(E) = \mathcal{O}(V + E)$
    

### Space Complexity: $\mathcal{O}(V)$

- **Color Array:** The `int[] color` array requires $\mathcal{O}(V)$ auxiliary space to store the color of each vertex.
    
- **Recursion Stack:** In the worst-case scenario (e.g., a straight line graph $0 \to 1 \to 2 \to \dots \to V-1$), the depth of the recursive DFS call stack can reach $V$, requiring $\mathcal{O}(V)$ stack memory.
    
- **Total Auxiliary Space:** $\mathcal{O}(V) + \mathcal{O}(V) = \mathcal{O}(V)$
