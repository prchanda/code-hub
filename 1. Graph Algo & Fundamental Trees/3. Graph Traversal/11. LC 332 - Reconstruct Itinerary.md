Question: https://leetcode.com/problems/reconstruct-itinerary/

Explanation: https://www.youtube.com/watch?v=ZyB_gQ8vqGA

```cs
public class Solution 
{
    public IList<string> FindItinerary(IList<IList<string>> tickets) 
    {
        // Use a Dictionary where each airport maps to a Queue of destinations
        Dictionary<string, Queue<string>> adj = new Dictionary<string, Queue<string>>();

        // Sort tickets lexicographically so they enter the queues in the correct order
        var sortedTickets = tickets.OrderBy(t => t[0]).ThenBy(t => t[1]);

        foreach (var ticket in sortedTickets) 
        {
            string src = ticket[0];
            string dst = ticket[1];

            if (!adj.ContainsKey(src)) 
            {
                adj[src] = new Queue<string>();
            }
            adj[src].Enqueue(dst);
        }

        List<string> result = new List<string>();
        Dfs("JFK", adj, result);
        
        // Hierholzer's algorithm builds the path in reverse, so reverse it back
        result.Reverse();
        return result;
    }

    private void Dfs(string airport, Dictionary<string, Queue<string>> adj, List<string> result) 
    {
        // While there are outgoing flights, dequeue them in O(1) time
        while (adj.TryGetValue(airport, out var destinations) && destinations.Count > 0) 
        {
            string nextAirport = destinations.Dequeue();
            Dfs(nextAirport, adj, result);
        }

        // Add to result when a dead end is reached
        result.Add(airport);
    }
}
```


### Time Complexity: $\mathcal{O}(E \log E)$

- **Sorting the Tickets ($\mathcal{O}(E \log E)$):** Sorting the initial list of tickets lexicographically by source and then by destination dominates the execution time, where $E$ is the number of tickets.
    
- **Building the Graph ($\mathcal{O}(E)$):** Inserting each sorted ticket into the dictionary and queues takes linear time.
    
- **DFS Traversal ($\mathcal{O}(E)$):** Hierholzer's algorithm visits every edge (ticket) and dequeues it exactly once in $\mathcal{O}(1)$ time.
    
- **Reversing the Result ($\mathcal{O}(V)$):** Reversing the final path takes time proportional to the number of airports ($V$). 

### Space Complexity: $\mathcal{O}(V + E)$

- **Graph Storage ($\mathcal{O}(V + E)$):** The dictionary stores $V$ unique airport keys and $E$ total destinations spread across the queues. 
    
- **Result List & Recursion Stack ($\mathcal{O}(V)$):** The result list holds $E + 1$ elements, and the maximum depth of the DFS call stack is bounded by the number of airports or edges ($V$), requiring linear auxiliary space.
