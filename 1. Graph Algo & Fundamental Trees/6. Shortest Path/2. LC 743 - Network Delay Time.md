Question: https://leetcode.com/problems/network-delay-time/

```cs
public class Solution 
{
    public int NetworkDelayTime(int[][] times, int n, int k) 
    {
        // 1. Build adjacency list graph (1-indexed)
        List<(int node, int weight)>[] graph = new List<(int node, int weight)>[n + 1];
        for (int i = 1; i <= n; i++)
        {
            graph[i] = new List<(int node, int weight)>();
        }

        foreach (int[] time in times)
        {
            int from = time[0];
            int to = time[1];
            int weight = time[2];

            graph[from].Add((to, weight));
        }

        // 2. Initialize distance array and Min-Priority Queue
        int[] distance = new int[n + 1];
        Array.Fill(distance, int.MaxValue);

        PriorityQueue<int, int> queue = new PriorityQueue<int, int>();
        distance[k] = 0;
        queue.Enqueue(k, 0);
        int maxDistance = 0;
        int visitedCount = 0;

        // 3. Dijkstra's Algorithm
        while (queue.TryDequeue(out int currentNode, out int currentDistance))
        {
            // If we've already found a shorter path to 'u', skip expanding its neighbors.            
            if(distance[currentNode] < currentDistance)
	            continue;
	            
			visitedCount++;
			maxDistance = currentDistance;
			
			// Return immediately if all 'n' nodes have been reached.
			if(visitedCount == n)
				return maxDistance;
			
            foreach ((int neighbour, int weight) in graph[currentNode])
            {
                int newDistance = distance[currentNode] + weight;
                if (newDistance < distance[neighbour])
                {
                    distance[neighbour] = newDistance;
                    queue.Enqueue(neighbour, distance[neighbour]);
                }
            }
        }

        return -1;
    }
}
```

## Complexity Analysis

Let $V = n$ be the number of nodes (vertices) and $E = \text{times.Length}$ be the number of directed edges.

### **Time Complexity:** $\mathcal{O}(E \log V)$

- **Graph Building:** Iterating through the `times` array takes $\mathcal{O}(E)$ time.
    
- **Dijkstra Traversals:**
    
    - In the worst case, every edge relaxation pushes a new entry into the priority queue. Thus, at most $E$ elements will be enqueued and dequeued.
    
    - Each operation on the priority queue takes $\mathcal{O}(\log E)$ time.
        
    - Since $E \le V^2$, $\log E \le 2 \log V$, which simplifies $\mathcal{O}(\log E)$ to $\mathcal{O}(\log V)$.
        
    - Total time spent on queue operations and neighbor iterations is $\mathcal{O}(E \log V)$.
        
- **Result Computation:** Scanning the `distance` array takes $\mathcal{O}(V)$ time.
    
- **Overall Time Complexity:** **$\mathcal{O}(E \log V)$** (or $\mathcal{O}(E \log E)$).
    

### **Space Complexity:** $\mathcal{O}(V + E)$

- **Graph Storage:** The adjacency list stores $V$ lists containing a total of $E$ edges, taking $\mathcal{O}(V + E)$ space.
    
- **Distance Array:** Stores distances for $n + 1$ nodes, taking $\mathcal{O}(V)$ space.
    
- **Priority Queue:** In the worst-case scenario without duplicate suppression, the queue can hold up to $E$ elements simultaneously, taking $\mathcal{O}(E)$ space.
    
- **Overall Space Complexity:** **$\mathcal{O}(V + E)$**.
